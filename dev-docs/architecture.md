## 2. 动态参数系统（核心架构决策）

### 2.1 设计目标

1. **不同类别参数不同**：示波器有带宽/采样率/通道数，电源有电压/电流/功率，万用表有位数/精度——不能用一套固定字段。
2. **同类产品参数结构一致**：所有示波器都按同一套参数模板填，方便对比和筛选。
3. **运营人员可维护**：后台可以定义参数模板，不需要改代码。
4. **支持前台选型**：用户可以按参数筛选产品（如"带宽≥100MHz、4通道"），可以对比多个产品。
5. **支持批量导入**：Excel 中按参数列批量填写。

### 2.2 三层结构

```
Category（产品类别，如"示波器"）
  └── ParamGroup（参数分组，如"基本参数""输入特性"）
       └── ParamDefinition（参数定义，如"带宽"，类型=number，单位=MHz，可筛选）
            └── ProductParamValue（产品参数值，如某型号带宽=500）
```

- **参数定义归类别，不归产品**。新增类别时定义一套模板，该类别下所有产品共用。
- **参数值归产品**，关联到参数定义，带类型化存储（数值/范围/枚举/布尔/文本）。

### 2.3 参数类型

| 类型 | 存储字段 | 示例 | 前台展示 | 筛选方式 |
|---|---|---|---|---|
| number | valueNumber | 带宽 500 | "500 MHz" | 滑块/输入范围（≥、≤、区间） |
| range | valueMin + valueMax | 频率范围 10Hz~100MHz | "10 Hz ~ 100 MHz" | 包含某值（如"覆盖 50MHz"） |
| enum | valueString | 通道数 = 4 | "4 通道" | 复选框多选 |
| boolean | valueBoolean | 支持触屏 = 是 | "✓" | 是/否 |
| string | valueString | 型号后缀 = HD | "HD" | 精确匹配/包含 |

### 2.4 前台选型功能

#### 产品列表页动态筛选器

进入某个类别（如示波器）后，左侧筛选栏**自动渲染**该类别标记为 `isFilterable` 的参数：

```
┌──────────────────────┐
│  筛选条件             │
│  带宽: [50] ~ [1000] MHz  ← 数值范围输入
│  通道数: ☑4  ☑8       ← 枚举复选
│  采样率: ≥ [2] GSa/s   ← 最小值输入
│  存储深度: ≥ [100] Mpts │
│  [重置] [应用筛选]     │
└──────────────────────┘
```

- 筛选条件通过 URL query params 传递（可分享、可收藏）
- 后端查询：先按类别取产品，再 join ProductParamValue 按参数条件过滤
- 多个筛选条件是 AND 关系

#### 产品对比

- 产品列表和详情页有"加入对比"按钮，最多对比 4 个产品
- 对比页：参数表横向排列，**差异项高亮**
- 只展示 `isComparable=true` 的参数，按分组排列
- 对比状态存在 localStorage（未登录用户也能用）

#### 产品详情页参数展示

- 按 ParamGroup 分组展示参数表
- 数值带单位，按 precision 格式化小数
- `isHighlight` 的参数在产品列表卡片和详情页顶部卖点区展示
- 参数值为空的参数不显示（避免大量"—"）

### 2.5 后台参数管理

#### 参数模板管理（按类别）

- 路径：后台 → 产品类别 → 选择类别 → 参数模板
- 功能：
  - 管理参数分组（新增/编辑/排序/删除）
  - 管理参数定义（新增/编辑/排序/删除）
  - 每个参数设置：名称（多语言）、类型、单位、是否筛选/对比/必填/高亮、校验规则
  - **从其他类别复制模板**（类似类别快速复用）
  - 预览：该类别下产品参数表单长什么样

#### 产品参数填写

- 产品编辑页 → "参数"Tab
- 自动按该产品所属类别的参数模板渲染表单：
  - number → 数字输入框 + 单位显示
  - range → 双输入框（最小值 ~ 最大值）+ 单位
  - enum → 下拉选择
  - boolean → 开关
  - string → 文本输入
- 必填参数校验
- 可标记该产品的某个参数为卖点（覆盖默认高亮设置）
- 未定义参数模板的类别，提示先去定义模板

### 2.6 性能考虑

- **筛选查询**：ProductParamValue 表对 (paramDefinitionId, valueNumber) 建索引，数值范围查询走索引
- **产品列表**：参数筛选可能涉及多次 join，使用 Prisma 的 `where` + `some` 条件，必要时用原始 SQL 优化
- **参数值缓存**：产品详情页的参数表变化频率低，可用 Next.js 的 `revalidate` 做增量静态再生（ISR）
- **对比查询**：一次取多个产品的全部参数值，在内存中组织对比表，不做复杂 SQL

### 2.7 扩展性

- 新增参数类型（如日期、文件）只需扩展 ParamDefinition.type 枚举和 ProductParamValue 的存储字段
- 参数模板支持版本化（后期）：修改参数定义时记录版本，已有产品参数值保留
- 参数单位支持多语言翻译（如 MHz 在中英文相同，但"通道"在中英文不同）

## 3. UI 技术栈

### 3.1 核心组合

| 层 | 技术 | 说明 |
|---|---|---|
| 样式 | Tailwind CSS | 原子化 CSS，精确控制外观，按需生成 |
| 基础组件 | shadcn/ui | 源码在项目内（components/ui/），可自由修改 |
| 复杂表格 | TanStack Table (@tanstack/react-table) | 后台产品列表、线索列表的排序/筛选/分页 |
| 表单 | react-hook-form + zod | 所有表单的校验和类型安全 |
| 富文本 | Tiptap | 后台新闻/文章内容编辑 |
| 图标 | Lucide React | shadcn/ui 默认搭配，简洁线性图标 |
| 图片 | next/image | Next.js 内置，自动优化 |

### 3.2 为什么不用 Ant Design / MUI

- Ant Design：组件全但外观是"后台管理系统"风格，做官网前台不够灵活，包体积大
- MUI：Material Design 风格强烈，定制成本高
- shadcn/ui：组件源码在项目内，外观完全可控，正好匹配"专属行业定制"需求

### 3.3 外观方向

- 主色：深蓝/科技蓝（仪器仪表行业专业感）
- 大量留白、清晰的参数表、专业感
- 参考：siglent.com、keysight.com 等仪器厂商官网
- 响应式：移动端优先，桌面端优化

## 4. 认证与权限

- 单管理员账号，session-based 认证（iron-session 或 next-auth credentials）
- 后台路由 `/admin/*` 受保护，未登录跳转登录页
- 询价接口有速率限制（同一 IP 每分钟最多 5 次）
- 密码 bcrypt/argon2 哈希存储
- 不引入多角色/多用户体系（第一版单账号够用）

## 5. 文件存储

- 第一版：本地存储（`public/uploads/`），宝塔面板管理
- 后期：可迁移阿里云 OSS，filePath 字段设计为相对路径，切换时只需改存储层
- 图片：产品图、品牌 logo、文章封面
- PDF：技术资料，支持下载计数

## 6. 部署架构

```
阿里云 ECS
  ├── 宝塔面板
  │    ├── Nginx（反向代理 + HTTPS + 静态资源）
  │    ├── Node.js（PM2 运行 Next.js）
  │    ├── PostgreSQL（数据库）
  │    └── 计划任务（数据库备份）
  └── 域名（已备案）→ HTTPS
```

- 部署流程：git push → 服务器 pull → pnpm install → prisma migrate deploy → pnpm build → PM2 重启
- 本地开发：Docker 跑 PostgreSQL 或本地安装，pnpm dev

## 7. 关键决策记录（ADR）

### ADR-001：选择 Next.js 全栈而非 JeeSite/WordPress

- **日期**：2026-08-31
- **决策**：使用 Next.js + TypeScript + PostgreSQL
- **原因**：团队不熟悉 Java，JeeSite 偏后台且二开量大；WordPress 定制受限；Next.js 是 AI 辅助开发效果最好的全栈框架，SSR 对官网 SEO 友好
- **替代方案**：JeeSite（否决）、WordPress（否决）、Strapi + Next.js（前后端分离，复杂度更高）

### ADR-002：动态参数系统按类别定义模板

- **日期**：2026-08-31
- **决策**：参数定义归属于产品类别，产品按模板填写参数值
- **原因**：仪器仪表不同类别参数差异大，固定字段不可行；自由 key-value 会导致同类产品参数混乱，无法筛选和对比
- **替代方案**：JSON 字段存参数（否决，无法查询筛选）、每类产品一张表（否决，类别多了维护成本高）

### ADR-003：UI 用 Tailwind + shadcn/ui

- **日期**：2026-08-31
- **决策**：Tailwind CSS + shadcn/ui + TanStack Table
- **原因**：组件源码在项目内可自由定制，匹配"专属行业定制"；AI 辅助效果好；轻量
- **替代方案**：Ant Design（否决，外观不够灵活）、MUI（否决，风格强烈）
